# ArtBalkon

Новый сайт компании: главная, семь страниц услуг, портфолио, три страницы реальных объектов, политика и согласие. Лёгкая сборка на Node.js без сторонних зависимостей. Страницы генерируются как HTML и доступны поисковым системам без JavaScript. JS нужен только для меню, форм, квиза и аналитики.

## Запуск

Нужен Node.js 22+. `npm run dev` собирает сайт и открывает сервер http://localhost:4173. Изменения в src/ и public/ автоматически пересобираются; для просмотра обновите страницу. `npm run build` обновляет dist/. `npm run check` проверяет страницы, ссылки и синтаксис. `npm test` проверяет обработку заявок. Установка пакетов не требуется.

## Где редактировать

- `src/content.mjs` — все цены в объекте prices, контакты, услуги, кейсы и их источники, вопросы, настройки аналитики.
- `src/components.mjs` — содержание и структура главной и остальных страниц.
- `public/styles.css` и `public/styles-extra.css` — стили; сборка объединяет их в один файл.
- `public/app.js` — квиз, валидация, меню, отправка и события.
- `public/assets/` — локальные фотографии WebP в двух размерах и шрифт Manrope.
- `scripts/leads.mjs` — проверка, сохранение и защита от повторной отправки.
- `docs/SOURCES.md` — подтверждённые сведения и источники.

## Заявки

По умолчанию сервер работает в режиме preview. Заявки сохраняются в `data/leads/`, не отправляются в компанию; экран благодарности явно сообщает об этом. Тестовая отправка не регистрируется как рекламная конверсия. Папка data недоступна через HTTP и исключена из Git.

Для реального приёма задайте переменные окружения из `.env.example`: `LEAD_MODE=live`, `PUBLIC_ORIGIN`, `LEAD_WEBHOOK_URL` (HTTPS), при необходимости `LEAD_WEBHOOK_TOKEN` и постоянный закрытый `LEAD_DATA_DIR`. Файл .env автоматически не загружается: можно использовать `node --env-file=.env scripts/server.mjs`. Секреты не помещать в src или dist. Хостинг должен запускать Node-сервер и иметь постоянный диск для заявок, HTTPS и резервное копирование. Срок хранения и удаление данных определяет оператор.

Успех показывается только после успешного ответа получателя. Ошибка доставки сохраняет заявку как pending; повторная попытка использует тот же ключ. Получатель должен поддерживать Idempotency-Key, чтобы исключить дубликаты при обрыве ответа. Есть серверная валидация, проверка Origin, ограничение размера запроса, частоты отправок и скрытое поле от простых ботов. При масштабировании на несколько процессов нужен общий ограничитель и хранилище идемпотентности.

При загрузке только dist на статический хостинг требуется отдельный рабочий API: укажите его адрес в integrations.leadEndpoint. Без API отправка не будет показывать ложный успех.

## Реклама и SEO

В `integrations` задайте metrikaId. Создайте цели: form_submit, quiz_start, quiz_complete, phone_click, whatsapp_click, telegram_click, portfolio_open. Успешные формы отслеживаются после подтверждения сервера. Имя и телефон в события не передаются. UTM и yclid сохраняются в рамках сессии и включаются в заявку при переходах между страницами. Записываются только разрешённые рекламные поля.

`externalScripts` принимает HTTPS-адреса скриптов, выданные Яндекс.Калибри и сервисом коллтрекинга (строки или `{src,id}`). Специфический код инициализации добавляется после получения настроек сервиса. Номер клика отслеживается через data-event, подмену номера выполняет выбранный провайдер. Неподтверждённые счётчики старого сайта не подключены. WhatsApp можно добавить после подтверждения номера и ссылки; сейчас показан подтверждённый Telegram.

Все страницы имеют H1, Title, Description, canonical, Open Graph и Schema.org. sitemap.xml генерируется из маршрутов. Canonical-домен — https://artbalkon.pro, изменить company.origin перед запуском на другом домене. Предпросмотр возвращает X-Robots-Tag: noindex. Числовой рейтинг Яндекса и неизвестные цены/сроки кейсов не выдуманы.

## Перед рекламным запуском

Подключить реального получателя заявок, проверить доставку, задать счётчики компании, подтвердить актуальность опубликованных цен и юридических текстов под выбранную инфраструктуру. Политика перенесена с действующего сайта, отдельное согласие подготовлено для новых форм. Проверка тепловизором отображается с сезонным ограничением.

## Проверки

Проверки структуры и ссылок: `npm run check`. Обработка заявок: `npm test`. Браузерное тестирование и фактическое получение рекламных событий сервисами не выполнялись. Дополнительный WebMCP start_balcony_calculation включается только при поддержке браузером; он лишь начинает квиз, не отправляет заявку. WebMCP в поддерживаемом контексте ещё не проверен.
