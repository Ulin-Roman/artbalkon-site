# ArtBalkon

Сайт компании: главная с комплексом работ под ключ, страницы остекления, отделки, утепления и ремонта балконов и лоджий, дополнительные направления, портфолио, три страницы реальных объектов, политика и согласие. Статическая сборка на Node.js с esbuild и PostCSS. Содержание генерируется как HTML и доступно поисковым системам без JavaScript. JS обеспечивает меню, формы, квиз, сравнение фотографий, калькулятор и аналитику.

## Запуск

Нужен Node.js 22+. `npm run dev` собирает сайт и открывает сервер http://localhost:4173. Изменения в src/ и public/ автоматически пересобираются; для просмотра обновите страницу. `npm run build` создаёт локальную папку dist/ (она не хранится в Git). `npm run check` проверяет страницы, ссылки, SEO-разметку и синтаксис. `npm test` проверяет обработку заявок. Перед первым запуском выполните `npm ci`.

## Где редактировать

- `src/content.mjs` — цены в объектах prices и finishingWallRates, контакты, услуги, кейсы и их источники, вопросы, настройки аналитики.
- `src/components.mjs` — содержание и структура главной и остальных страниц.
- `public/styles.css` и `public/styles-extra.css` — стили; сборка объединяет их в один файл.
- `public/app.js` — квиз, калькулятор отделки, валидация, меню, отправка и события.
- `public/assets/` — исходные фотографии, подготовленные WebP-варианты и шрифт Manrope.
- `scripts/leads.mjs` — проверка, сохранение и защита от повторной отправки.
- `docs/SOURCES.md` — подтверждённые сведения и источники.

## Заявки и публикация

Основной сайт — https://artbalkon.site на REG.RU. Workflow `.github/workflows/deploy-pages.yml` собирает его с `SITE_BASE_PATH=/`, `SITE_ORIGIN=https://artbalkon.site` и `SITE_MAIL_FORMS=true`, проверяет сборку и загружает `dist/` по FTP. Пять пользовательских форм отправляют заявки в `/api/leads.php`; PHP-обработчик отправляет письмо на фиксированный адрес balkonart@yandex.ru. Для работы нужны PHP 7.3+ и настроенная почтовая служба хостинга. Подробности и проверки — в `server/README.md`. Секреты FTP находятся в GitHub Actions Secrets и не включаются в сборку.

Успех показывается после принятия письма почтовой службой сервера. Это ещё не подтверждает получение во входящих; доставку проверяют отдельно в рабочем ящике. Обработчик проверяет согласие, поля, Origin, размер запроса, частоту и повторную отправку. В закрытой временной папке на 24 часа сохраняются только хеши, идентификаторы и время; имена, телефоны и ответы в этот журнал не записываются.

GitHub Pages — статический предпросмотр: https://ulin-roman.github.io/artbalkon-site/ . Репозиторий — `Ulin-Roman/artbalkon-site`. При каждом push в `main` workflow сначала собирает Pages с `SITE_BASE_PATH=/artbalkon-site/`, `SITE_ORIGIN=https://ulin-roman.github.io/artbalkon-site` и `SITE_STATIC_ONLY=true`, запускает проверки и тесты, публикует через Pages Actions. Затем собирает и публикует версию REG.RU. После FTP workflow проверяет опубликованные страницы, переходы и PHP endpoint без отправки заявки.

В Pages-версии отправка форм отключена, формы сообщают об этом и показывают телефон. Страницы имеют `noindex,follow`, sitemap не публикуется. Сборка обновляет внутренние ссылки, CSS, JS, `srcset`, шрифты и изображения с префиксом `/artbalkon-site/`, а также создаёт `.nojekyll`. `public/app.js` загружает `site-config.json` рядом со скриптом. Для ручной проверки задайте перечисленные переменные соответствующей версии, затем выполните `npm run build` и `npm run check`.

## Локальные формы и необязательный Node webhook

По умолчанию `npm run dev` запускает локальный Node-сервер в режиме preview. Заявки сохраняются в `data/leads/` без отправки в компанию; экран благодарности сообщает о тестовом режиме, рекламная конверсия не регистрируется. Папка `data/` недоступна через HTTP и исключена из Git. Локальный сервер не исполняет production PHP.

Для отдельного Node-развёртывания с HTTPS webhook предусмотрены переменные из `.env.example`: `LEAD_MODE=live`, `PUBLIC_ORIGIN`, `LEAD_WEBHOOK_URL`, при необходимости `LEAD_WEBHOOK_TOKEN` и закрытый постоянный `LEAD_DATA_DIR`. Этот режим не используется текущей публикацией на REG.RU. Файл `.env` автоматически не загружается; пример запуска — `node --env-file=.env scripts/server.mjs`. Секреты не помещать в `src/` или `dist/`. Получатель webhook должен поддерживать `Idempotency-Key`: ошибка доставки сохраняет заявку как pending, повторная попытка использует тот же ключ. Для нескольких процессов требуются общие хранилище идемпотентности и ограничитель частоты.

## Реклама и SEO

В `integrations` задайте metrikaId. Создайте цели: form_submit, quiz_start, quiz_complete, phone_click, whatsapp_click, telegram_click, portfolio_open. Успешные формы отслеживаются после подтверждения сервера. Имя и телефон в события не передаются. UTM и yclid сохраняются в рамках сессии и включаются в заявку при переходах между страницами. Записываются только разрешённые рекламные поля.

`externalScripts` принимает HTTPS-адреса скриптов, выданные Яндекс.Калибри и сервисом коллтрекинга (строки или `{src,id}`). Специфический код инициализации добавляется после получения настроек сервиса. Номер клика отслеживается через data-event, подмену номера выполняет выбранный провайдер. Неподтверждённые счётчики старого сайта не подключены. WhatsApp можно добавить после подтверждения номера и ссылки; сейчас показан подтверждённый Telegram.

Содержательные страницы имеют H1, Title, Description, canonical, Open Graph и Schema.org. sitemap.xml содержит только индексируемые маршруты. Canonical использует SITE_ORIGIN: https://artbalkon.site для основного хостинга и https://ulin-roman.github.io/artbalkon-site для GitHub Pages. Короткие страницы перехода имеют noindex и canonical целевой страницы. Локальный предпросмотр возвращает X-Robots-Tag: noindex. Неизвестные цены и сроки кейсов не выдуманы.

## Перед рекламным запуском

Проверить доставку заявок в рабочем ящике, счётчики компании, актуальность опубликованных цен и юридических текстов под выбранную инфраструктуру. Политика перенесена с действующего сайта, отдельное согласие подготовлено для новых форм. Проверка тепловизором отображается с сезонным ограничением.

## Проверки

Проверки структуры и ссылок: `npm run check`. Обработка заявок: `npm test`. Браузерные проверки в Chromium охватывают меню, формы с подменённым получателем, галереи, калькулятор, переходы и отсутствие горизонтального переполнения на 320, 375, 412, 640 и 1280 px. Фактическое получение рекламных событий внешними сервисами требует проверки на опубликованном сайте. Дополнительный WebMCP start_balcony_calculation включается только при поддержке браузером; он лишь начинает квиз, не отправляет заявку. WebMCP в поддерживаемом контексте ещё не проверен.


## Мобильная совместимость и оптимизация

- Сборка CSS/JS рассчитана на Safari 15.4+, Chrome 100+ и Firefox 100+; современные декоративные свойства используют обычные CSS fallback-значения.
- У сравнений «до/после» явно задана полная ширина вложенной сетки: это обход особенности размеров дочерних элементов кнопки в WebKit. Мобильный `sizes` соответствует половине карточки.
- Используемые исходные фотографии сохраняются; неиспользуемые ассеты не попадают в публикацию. Сборка минифицирует CSS/JS и добавляет версии по хешу содержимого.
- Проверяйте геометрию страницы, карточек и диалогов на 320, 375, 412, 640, 768, 820, 1024 и 1280 px. Эмуляция размера в Chromium не заменяет проверку настоящего Safari на iPhone/iPad.
- Локальный обработчик поддерживает contact, quiz, callback, callback-popup и transformation. Последняя форма сохраняет техническое название выбранной работы.

## Калькулятор отделки на главной

После вариантов отделки расположен интерактивный калькулятор (src/finishing-calculator.mjs). Размеры задаются в сантиметрах. Все семь групп выбранных работ входят в предварительную сумму: стены, потолок, пол, наружная отделка, освещение, остекление и утепление. Общий прайс услуг сайта независим от тарифов калькулятора.

Числовая модель public/calculator-estimate.mjs сверена с публичным калькулятором https://balconia.ru/#calc 13 октября 2026 года. При длине L и ширине W в метрах используются: стены L×2,6 + W×2×2,6 + L; пол и потолок L×W; переднее остекление L×1,6; утепление W×2,6 + L×2×2,6 + W; наружная отделка W погонных метров. Точечное освещение считается пропорционально длине (1700 ₽ за участок 1,5 м), подвесное — фиксированно 4500 ₽. Каждая строка округляется вверх до рубля в порядке операций эталона. Начальное нулевое утепление и зависимость старого аккумулятора эталона от истории кликов не повторяются: сумма всегда пересчитывается из текущего выбора. Эталонные суммы покрыты scripts/calculator-estimate.test.mjs.

Площадь стен считается без вычета квартирных проёмов; условная схема и размеры не заменяют замер. Выбранная комплектация, все строки и их сумма передаются в поле calculation формы callback и сохраняются Node-обработчиком или включаются в письмо PHP-обработчиком. На GitHub Pages действуют обычные ограничения статического режима.

## Перенос страницы «Под ключ» на главную

Главная содержит объединённую страницу «Балконы и лоджии под ключ». Старый адрес `/balkon-pod-klyuch/` исключён из sitemap и сохраняется только как переход на корень. На Apache сборка создаёт `.htaccess` с HTTP 301; GitHub Pages использует короткую страницу перехода с `noindex` и canonical главной. Старые адреса лоджии под ключ, крыши, мебели и электрики ведут сразу на главную.

Сборка дополнительно объединяет шесть побайтно одинаковых изображений в публикации после `Buffer.equals`. Исходники и responsive manifest сохраняются; если изображения станут разными, объединение автоматически пропускается. Workflow проверяет обе сборки перед публикацией и постоянные HTTP-переходы после FTP.
